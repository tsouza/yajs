=== Interpretation ===

Both real selector shapes this issue asked about regress end-to-end,
despite the matching-layer-only benchmark (bench.ts, walking already-parsed
JS object trees with no tokenizer/StreamPosition-output overhead) showing
apparent speedups of 1.46x and 1.89x respectively for the same two
selectors. The matching-layer-only number was misleading: it compared the
real backward-walk ALONE against the automaton ALONE, but in the real
pipeline StreamPosition is maintained regardless of which matcher is used
(startObjectEntry/stepIntoObject/etc. still have to run for path-string
output and dispatcher bookkeeping) - so the automaton's own per-event cost
(this prototype's lazy-DFA transition lookup builds a template-literal
string key and does a Map hash+lookup on every single event, plus a SECOND
state/bits stack pushed and popped in lockstep with StreamPosition's own)
is purely ADDITIVE overhead on top of that already-necessary bookkeeping,
not a replacement for the backward-walk's cost. For a selector this short
($..plugins is Root + Descendant + one Child; even $..* is Root +
Descendant + one Wildcard), the real backward-walk was already cheap enough
that this prototype's own implementation overhead exceeds what it saves.
